# Slime Tech Compat：受け入れ試験仕様

この文書は、実機で行う受け入れ試験の操作と合格条件を定めます。実施する項目を選び、下記の形式で結果を記録してください。現在の実績と次の試験は[検証記録](docs/VERIFICATION.md)を参照します。参考0.3.0のモデル試験記録は、参考ソース内の `docs/VERIFICATION.md` にあります。

## 1. 記録の単位

各試験について、次を保存してください。

```text
test_id / issue_id
実施段階：純粋関数 / fixture / 実バイトコード / 実Mixin / NeoForge統合 / 手動UI
元MOD・パッチ・NeoForge・Minecraft・JEI・追加MODの版とSHA-256
設定値 / world seed等の再現条件 / 座標・ディメンション
準備 / 操作 / 期待値 / 実測値
PASS / FAIL / SKIP / NOT_RUN
実行コマンド / ログ / スクリーンショット等の証跡
未実施の場合の理由と次の手順
```

`SKIP`、`NOT_RUN` と `PASS` は別々に集計します。モデル試験、ビルド成功、サーバー起動成功、クライアント描画成功は独立した検証です。

## 2. 開発基盤・適用試験

| ID | 試験 | 合格条件 |
|---|---|---|
| ENV-01 | 元JAR・参照ソースのハッシュ照合 | INPUT_MANIFESTと一致。違えば対象を再監査 |
| ENV-02 | wrapperからclean build | 実Minecraft/NeoForge/JEI依存物でコンパイル成功 |
| ENV-03 | 通常JARの同梱物検査 | 独立パッチのみ。元MODのclass/assets、スタブ、fixture、テスト、解析生成物を含まない |
| ENV-04 | 実Mixin変換 | 対象3 Mixinと全想定注入箇所が実エンジンで成立。想定しない欠落や二重適用がない |
| ENV-05 | JEIなし専用サーバー | 起動・ワールドロード・保存・終了が正常。クライアントクラス読込エラーがない |
| ENV-06 | JEIありクライアント＋接続 | 起動、専用サーバー参加、退出、再参加が正常 |
| ENV-07 | JEIなしクライアント | パッチのゲームプレイ修正が動き、任意依存の欠落でクラッシュしない |
| ENV-08 | 対象版不一致 | 対応外版と注入不一致を説明付きで検出。サイレントに一部だけ失敗しない |
| ENV-09 | 不正な設定値・未知キーなど | 空ファイル、未知キー、不正boolean、上限外値の扱いが仕様どおり。既存設定を破壊しない |
| ENV-10 | 最小構成と実使用構成 | 必須依存のみの試験後、Ore Slimes、RS、FTBIC等を順に追加し失敗点を切り分ける |

参考版はモデル試験にJDK 21、通常ビルド設定にJava 25を使っています。モデル用JDKがそのままMinecraft起動要件だとは扱わず、実際の対象版の要件を確定してください。

## 3. 採掘・回収：ST-001

対象9機械を空の状態で設置し、サバイバル・適切なツルハシで回収してください。破壊速度、本体数、シルクタッチ要否、適正ツール条件を記録します。

内容入りでの試験は別コピーで行います。アイテム、流体、電力、アップグレード、モードの保持状況を元MODとパッチで比較し、「本体回収できる」ことと「内容を全部保持する」ことを分けて説明してください。

## 4. JEIと初回導線：ST-002、003、011、012

1. Slime Block、かまど、通常燃料、空バケツ、Casting Moldを用意し、Gel Ingotを一度も所持しない状態から開始する。
2. かまどの特殊処理のタイミング、燃料スロットのバケツ条件、隠し流体へ変換された状態を確認する。
3. Casting MoldへCondensed Slimeを注入し、200 tickという既存記録と実際の出力を照合する。
4. Basic / Reinforced Fluid PipeでCondensed Slime・水・溶岩の可否を比較する。
5. JEIでGel IngotのR、Casting MoldのU、流体からの用途検索、機械カテゴリ、情報ページを確認する。
6. Mixerの表示と実際の処理について、アイテム1/2個、空スロット、配置、流体249/250 mBおよび999/1000/1001 mB、出力詰まりを確認する。
7. Ore Slimesあり／なしの両構成を試す。存在しない素材のレシピをAIRで登録しない。
8. 日本語・英語で項目欠落、はみ出し、意味の逆転がないことを確認する。設定OFFでもONの機能を断定する説明になっていないことを確認する。

GUI試験ができない環境ではモデル試験と登録ログを残し、R/U検索・描画は `NOT_RUN` にします。

## 5. Fluid Tank：ST-004、015、PATCH-001

### 種類と量の保存

次のケースを、通常配管・手動バケツ・GUIスロット・一般Fluid Capability経由で試してください。

| ケース | 期待する性質 |
|---|---|
| 水＋水、溶岩＋溶岩 | 正常な合算と転送 |
| 水＋溶岩、MOD流体A＋B | 混在を検出し、内容を保持したまま転送停止 |
| 水－空Tank－溶岩 | 空Tank越しの混在も検出 |
| 空Tankのみ、0 mB | 偽の流体種類や残量を作らない |
| 中身あり・ID空／未登録 | 推測変換せず保留 |
| 負数、容量超過 | 破壊的な補正をせず、診断可能な状態にする |
| パッチ導入前から混在した保存 | ロード時に一種類へ勝手に統合しない |
| 切断・再接続・再保存 | 内容が保存され、正常化後に再開 |

各ステップで「流体IDごとの総量」を記録してください。合計mBだけが等しくても水が溶岩へ化けていれば不合格です。

### トランザクションとキャッシュ

- simulateを繰り返しても元の量・ID・ワールドが変わらない。
- 実行を中止したtransactionの後で内容が元へ戻る。
- 同じtickでタンクを充填／切断／再連結しても古い安全判定を使わない。
- 停止状態のGUI、RS表示、ログが保存内容の消去を意味しないことを確認する。

### チャンク・上限

1/16/64/256/512/513台と、設定上限の前後を試します。チャンク境界、隣接チャンク未ロード、再ロードで強制ロード・無限探索・部分内容だけの安全扱いがないことを確認します。空の隣接チャンクが未ロードなだけで停止する保守的挙動は、仕様と運用負担を明記してください。

## 6. Pump：ST-005、006、007

### 保存形式

- 元形式の固定番号1〜4をそれぞれ部分充填して保存・ロード。
- 0.3.0のレジストリID付き形式を次版へ移行。
- 動的番号しかない旧Pumpを、次セッションで同番号が別流体になる条件でロード。
- 未登録IDを保存し、流体提供MODを戻してから再読込。
- 不正量、種類不明、空Pump、スキーマ番号が未来値の場合を試験。
- 2回以上の保存／ロードで保留情報・元コード・量・電力を保持。

### ワールド流体源の変更

バッファに溶岩を残したままsourceを撤去、水へ変更、元へ戻す操作を行います。旧内容が消失・別流体化・不適切に追加されないこと、空になった後の新種選択が可能なことを確認します。

### 任意設定

`blockNonWaterWorldSources=false/true` の両方で、水・溶岩・独自流体を試験します。trueは水以外、溶岩を含む汲み上げを拒否します。禁止設定は既に保存されたバッファの削除ではありません。

保留Pumpは稼働・抽出を止める一方で、情報を保存し、読み取り専用の診断から原因と対象座標を確認できるようにします。

## 7. Grinder：ST-008

設定OFF/ONについて、新規設置とロード済み機械を分けて試します。

| 準備 | ON時の期待値 |
|---|---|
| 新品 | 0 FE |
| 保存済み2,000 FE | その値を保持 |
| Energyキー欠落 | 新品相当の方針どおり |
| 0 / 14 / 15 / 119 FE | 完成不可 |
| 120 FE、1加工 | 1回分だけ完成し、120 FEを支払う |
| 進捗途中にFEを抜く | 不足状態で出力を確定しない |
| 出力スロット満杯 | 素材・電力を不適切に消費しない |

120 FE/加工という既存記録を出発点にし、15 FE/t等の独自変更を混ぜないでください。

## 8. かまど：ST-009、022、023

### 端数変換の追加仮説

| 初期隠し流体 | 素材 | 操作 | 確認 |
|---:|---:|---|---|
| 7,000 mB | Dried Slime×1 | 特殊処理 | 1個を消費し1,000 mBだけ増加 |
| 7,500 mB | ×1 | 特殊処理 | 素材未消費の500 mB増加が起こらない |
| 7,999 mB | ×1 | 特殊処理 | 素材未消費の1 mB増加が起こらない |
| 8,000 mB | ×1 | 部分抽出→再処理を反復 | 1個を繰り返し利用した増殖がない |
| 任意 | ×1 / ×2 / ×64 | 空バケツ0 / 1 / 2個 | バケツ化と隠し保存の二重計上がない |

初期流体＋消費素材×1,000 mB＝最終保存流体＋抽出量＋バケツ化された流体、という収支を追ってください。途中保存・再起動を挟むケースも含めます。到達条件が成立しない場合は、その理由を記録して仮説を棄却します。

### ライフサイクルと性能

充填後の破壊、同座標再設置、他ブロックへの置換、別座標、別ディメンション、アンロードを比較します。処理の対象追跡や掃除を変更した場合は、かまどのLIT状態更新等を撤去と誤認しないことも確認します。

チャンク数・かまど数を変えてserver tickの走査数・時間を計測します。性能対策で初回バケツ手順や通常精錬が壊れないことを確認します。

## 9. 他MOD連携と運用

元JARを用意できた組合せから段階的に確認します。

- RS Importer / Exporter / External Storage ↔ Slime Tech Fluid Tank / Pump。
- Slime Tech配管 ↔ NeoForgeが公開する流体ハンドラ。大釜・他MODタンクの実可否はそこで確定する。
- 集約タンク ↔ RS ↔ FTBIC Geothermal Generator。
- Slime Techの電力設備 ↔ LTX Energy Cell Array / RS Controller。
- Item Tube ↔ Container実装とCapability専用実装の双方。

これらは連携の受け入れ対象であり、過去会話の「つながるはず」を検証結果の代わりにしません。

## 10. リリース判定

必須範囲はBUILD-001、ST-001〜006、PATCH-001の解消・実証です。ST-022で増殖を再現した場合はその修正も必須に昇格します。

JEI表示・ゲーム内操作を含めて完了した場合だけ、その範囲を検証済みと表示してください。GUI未検証、特定他MOD未入手、性能未測定などの残件があれば、成果物の検証段階に明記します。

JAR、ソース、SHA-256、依存バージョン、設定、移行手順、ロールバック、既知制限をセットで公開準備してください。本番への自動導入はこの作業には含みません。
